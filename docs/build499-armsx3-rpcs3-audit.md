Status: Core compiled and verified; private IPA composition pending. No physical-device validation or measured FPS gain.

## Selected changes

1. Correct the u64 SHUFB insertion pattern. The old pattern matched a malformed shuffle and missed the valid single-lane insert; scalar differential testing finds one wrong entry among the 30 patterns. Use upstream RPCS3 d7f4c3507be3aaef631067aca9f0d0c8c89e9eea, also public ARMSX3 e99467b5bafddcb467e77ccd670e815a02c9218e. Preserve every other lowering and the generic fallback.
2. Enumerate a conditional direct branch's taken target first, followed by its fallthrough, retaining one target if both coincide. Use upstream RPCS3 9c8e4349b7296c5e14d7fde9cc4d88a8b69f2fca, ARMSX3 ddd902e766799f57f68be386fe10891f289d5b3d. Test with the actual decoder, forward/backward/self branches and local-store wraparound.
3. Independent compile-path diagnostic reduction: ordinary block-build messages use trace (the logger filters it before formatting at its default notice level). A decrementer read no longer forces a complete disassembly in normal use. Explicit SPU debug and failed debug-file-write diagnostics remain. Aggregate JITPROF/SPUPROF remain unchanged. This removes avoidable compilation work; it is not a proven steady-state FPS gain.
4. Extend the configure-time SPU object identity to cover SPUThread.cpp and SPUOpcodes.h, which affect branch discovery. Existing identity/relocation validation, size limits, eviction and stored symbol resolution remain. The SPU cache rebuilds once; PPU codegen inputs and PPU object naming remain unchanged.

## Preserved and rejected

The ARM64 TBL byteswap, byte arithmetic fast paths, x86-only guards, NEON reservation copies, wake-on-range-lock-clear, bounded persistent SPU objects, InstCombine calling-convention correction and cache-pressure fallback already exist. No duplicate import. NeoSwap allocation/eviction/storage services, coherently aliased guest memory, GPU retirement, JIT arenas and entitlements remain unchanged. No ARM host address is serialized by these changes.

The newer ARMSX3 FIFO fetch fix targets a puller whose public GET reflects fetched commands. Our older FIFO publishes consumed positions, so the patch's prerequisite is absent; do not transplant a newer FIFO state machine. Android scheduling/Turnip linear images and driver patches are platform-specific. The graphics-pipe conversions are present in public VKResolveHelper.cpp and are explicitly enabled only for Adreno/Turnip; VKTexture.cpp also replaces many GPU conversions with CPU conversions to avoid an Adreno engine-switch hang. The supplied IPA contains the corresponding controls, but neither their effective configuration nor an Apple-GPU benefit is proven. Do not copy third-party binaries or force these paths on Apple GPUs. Memory-cap increases and global SPU compile pauses are not adopted.

These are host component results, not gameplay or iPhone throughput. ## Additional binary findings and limits

- ARMSX3's main executable is 80,568,256 bytes, SHA-256 `26b6b3f8d14a947fe691910180eeaec60d49a5af4aa60aca8d2d8128cde531fb`. NeoStation 498's signed embedded Core is 77,573,456 bytes, SHA-256 `be64e13940f561b51d3828b59cea9393bbab30439c8f8ef77e1d19b2b527d650`; this differs from the unsigned source artifact because packaging changes its Mach-O/signature. File size is not a memory or speed benchmark.
- ARMSX3 links the PS3 engine, MoltenVK, LLVM and FFmpeg into its main executable; the only separately bundled dylib is librashader. Its JITEnabler extension is a separate 5,947,792-byte executable. NeoStation instead lazily loads libRPCS3Core.dylib through its existing ABI-30 host bridge and shares a frontend with other emulators.
- Both images identify LLVM 22.1.8, but ARMSX3 embeds LLVM revision `6b1ab124ef73d946bb25b48cd7a553f0b825de35`, NeoStation `ca7933e47d3a3451d81e72ac174dcb5aa28b59d1`. Preserve NeoStation's reviewed AArch64 GHC emergency-spill patch and coherent object identity rather than replacing LLVM by a same-number library. ARMSX3's exact compiler flags/ThinLTO/fast-math settings cannot be established from these metadata alone.
- ARMSX3's signed XML entitlements contain increased-memory-limit and get-task-allow; its extension has get-task-allow. This shows requested signing attributes only, not effective privileges after sideload signing. The Core dylib has no separate entitlement payload; NeoStation's host/extension signing remains responsible. No new entitlement or internal VPN is introduced.
- The SPU branch-target routine is symbol-addressable at 0x100cb8ef0 in the supplied IPA. The public post-IPA fix is imported for its independently tested semantics; the unresolved private source is never represented as the public master tree.
- The GPU conversion controls are public Adreno fixes, not evidence of an Apple-specific optimization. Android affinity, Turnip drivers, VRAM-cap increases and global compile pauses are rejected for the same reason: their benefit and correctness on this iPhone architecture are not demonstrated.
- The NeoStation Core's legacy embedded build-information JSON still contains an older upstream identifier. Provenance here uses the canonical-source manifest, source input hashes and successful build artifact identity, rather than treating that legacy banner as the exact source revision.

# Switch 2 playlist (S2Arm) — parallel studies and proposed batches

**11 November 2026. Source reading only: nothing here was compiled, executed or measured,
and nothing is committed to.** Requested by the maintainer while the device probe of the
[feasibility prototype](s2arm-prototype-2026-11-10.md) waits for a test IPA. That probe
remains the gate: if it fails without a workaround, the batches below are void.
S2Arm at `6b6a5715`; RewindBox at `Claude` `d6b15c86` plus this branch.

## 1. JIT helpers of the other engines

Read in `packages/*_jit_helper`, `packages/*_internal_bridge` (ARMSX2, RPCS3, Dolphin);
MeloNX is the reference already described in the prototype document.

| | MeloNX | ARMSX2 | RPCS3 | Dolphin |
| --- | --- | --- | --- | --- |
| Helper | own extension, universal script | own extension, same commands (0–3) | own extension, same commands (0–3) | own extension, StikJIT legacy script, no script in the repository |
| Detaches before play | yes | yes (`Armsx2InternalBridgePlugin.mm:1550-1563`) | yes (`Rpcs3JitBridgePlugin.mm:609-634`) | yes (`DolphinInternalBridgePlugin.mm:1529`) |
| JIT transaction | once per process (`arenaReady`) | a fresh one at every launch (`Armsx2InternalBridgePlugin.mm:594-613`) | not determined; arena policy fixed once the Core is loaded (`Rpcs3InternalBridgePlugin.mm:1119-1121`) | a new helper at every launch (inferred) |
| Address chosen by the process | never exercised | caller not found | reserves chosen ranges early, hands them to its Core (`Rpcs3EarlyAddressSpaceEscrow.h`) | not determinable from the app source |

- The ARMSX2 and RPCS3 scripts were not compared line by line with the MeloNX one.
- "Once per process" is therefore a property of the MeloNX bridge, not an established iOS
  rule: ARMSX2 re-attaches at every launch. Whether a second transaction works after another
  engine's is unobserved.
- RPCS3 is the in-app precedent for what S2Arm needs: an address-space reservation taken
  before other allocators, then JIT code inside it. Its policy header quotes an address
  census (IPA 674, iOS 27 beta): 538 MiB free below 64 GiB and a free 64 GiB gap at 448 GiB,
  i.e. below 2^39. How its Core makes the chosen address executable, and on which builds
  this is device-observed, has been asked of the main session.
- No "restart between engines" guard was found in the JIT bridges; the only cross-engine
  effect found is the MeloNX memory quarantine (`lib/services/melonx_internal_service.dart:47-62`).
- libretro cores only read `CS_DEBUGGED`; they have no helper.

## 2. The S2Arm runtime as a guest of RewindBox

| S2Arm today | Source | Needed in RewindBox |
| --- | --- | --- |
| Signal handlers for SIGSEGV, SIGBUS, SIGILL, SIGTRAP, SIGFPE, SIGABRT installed with no previous action kept | `platform/apple/plat_apple.c` `plat_fault_install`, `runtime/src/crash.c` `s2a_crash_install` | chain to the handlers already present (crash journal, NativeAOT, Ryujinx) for faults outside its window and modules |
| SIGSEGV is on the normal path: write tracking of GPU data, read emulation through aliases | `runtime/src/crash.c`, `graphics/track/` | keep; its cost on an iPhone is unmeasured |
| Window reserved in a constructor, before any other allocator; fallback to the largest hole below 2^39 (2 GiB minimum) | `runtime/src/vawin.c` `vawin_boot`, `pick_hole` | reserve at app start (the RPCS3 escrow is the model) or accept the fallback; the probe measures the hole |
| Owns `main` and `UIApplicationMain`, sets `DOTNET_GCSegmentSize` and `MTL_SHADER_CACHE_SIZE` for the process | `runtime/src/host_main.c`, `ios/app.m` | a library entry started from a RewindBox view controller; no process-wide environment |
| Services: NativeAOT **static** library linked into its executable | `services/aot/S2A.Aot.csproj` (`NativeLib` Static) | a separate framework, so that it does not share an image with `MeloNXCore.framework`; two NativeAOT runtimes in one process is unverified |
| `_exit` / `exit` on failures and at the end of tool runs | `runtime/src/host_main.c` | return to the library instead |
| In-process session restart and a multi-title "library first" container already exist | `runtime/src/session.c`, `host_main.c` `s2a_host_rebuild`, `main` | usable base for "close the game, open another"; on iOS code pages are reused in place for the same image |

The earlier statement "one game per process, then exit" is too strong: S2Arm has an
in-process restart. Whether it can load a *different* game's code in the same process
depends on the JIT answers (new executable memory after detach, or one arena reused).

## 3. Preparing a game without a computer

Today: `pack/oneclick/oneclick.sh` → unpack → seed root → `pack/refresh.sh` → `pack/ipa.sh`;
about 2 000 lines of bash, and at least 5 400 lines of Python on the required path (a lower
bound: the shader, translator and job internals were not counted).

| Stage | Today | Required to boot | On the phone |
| --- | --- | --- | --- |
| Unpack NSP/XCI | C# on LibHac (`pack/nx_unpack`), needs the user's keys | yes | port into a NativeAOT library; RewindBox already ships LibHac and key handling for MeloNX |
| Seed root | Python clone of exefs/romfs | yes | replace by direct layout; avoid the second romfs copy |
| Rewrite | C library + Python helpers (`tools/addr_need.py`, `runtime/rewriter/nro_to_nso.py`, `graphics/widen/scan/wide_scan.py`, `graphics/nvn/games/profile_guess.py`, `tools/nro_exports.py`) | yes | library as is (host-proved here); helpers to port |
| Caps | bash (`pack/stage_caps.sh`, not read) | yes for their packaging | to read, then port |
| System data | Python (`pack/stages/sysdata*.py`); synthesised when no firmware is given | yes (fonts) | port |
| Title metadata, DLC | nx_unpack | metadata yes, DLC optional | with unpack |
| RomFS index | C# (`services/romfs_index`) | yes (inferred) | with the services library |
| Widescreen UI layout | Python + `yaz0enc.c` compiled at pack time | no | leave out, or prebuild the encoder |
| Widescreen, fps, community patch tables | Python + maintainer data | no | leave out at first |
| Shader library | `xcrun metal`, .NET, C++ | an empty "runtime-only" library is accepted by the packager; boot without it not determined | runtime compilation only; first-use stutter expected, unmeasured |
| Bundle, embed, sign | Python, codesign | replaced | data files loaded through JIT memory |

- No complete on-device path exists in S2Arm on either platform. Android has an opt-in
  in-process rewrite (`android/rewriter/`), not accepted under the app's own UID per its
  README; unpack, system data, index and package assembly still run on a computer.
  `runtime/src/pack_apply.c` only unpacks a package pushed from a computer.
- Storage: romfs is fully extracted and the resource pack is a second copy; S2Arm quotes
  10–34 GB packs for nine games and one 17.6 GB romfs file.
- Not determined: boot with an empty shader library, what system data needs from user
  firmware, the caps stage, the size of the C# unpacker.

upstream moving fast (the pin is one day old), and the amount of S2Arm source that would
enter the repository under Apache-2.0 next to GPL-3.0 code (compatible, with notices).

## 6. Engine integration plan (11 Nov, after the device gate; maintainer: up to import and play)

Facts read at the pin (file:line in the S2Arm tree):
- The iOS app is already game-independent: a prebuilt shell (`make ios`, `runtime/build.mk:85-199`)
  with three Mach-O images (executable with the C runtime, UIKit host and the NativeAOT services
  linked statically; `NS2Pro.framework`; `S2AImages.dylib` = the game's rewritten code). Deployment
  target iOS 18.0; S2Arm builds with the iOS 27 SDK (`tools/toolchain.env`).
- Game code is mapped from the image pack by `runtime/src/imgpack.c` (`s2a_imgpack_map`: file
  `mmap` R|X after `F_ADDFILESIGS_RETURN` + `F_CHECK_LV`, i.e. a signed file) from the iOS path
  of `runtime/src/loader.c:682-762`. The macOS path (`loader.c:777-838`: copy into RW memory, key
  page, seal RX) is the model for loading into JIT pages. Pack format `S2AEMB01`, 16 KiB blocks.
- The services are one NativeAOT image, "the only one per process" (`services/aot/S2A.Aot.csproj:1`),
  exports `S2A_Init`, `S2A_InitSession`, `S2A_ShutdownSession`… (`services/S2A.Services/Exports.cs`).
- A multi-title container mode exists: the library shows first and the host starts after a game is
  selected (`runtime/src/host_main.c:443-462`, `launchctx.c`).
- RewindBox loads MeloNX's NativeAOT Core with `dlopen(RTLD_LOCAL)` only when a Switch game starts
  (`packages/melonx_internal_bridge/ios/Classes/MeloNXRuntimeAPI.swift:92`).

Design decisions (to verify on device):
1. The engine is one dynamic framework (runtime + graphics + services + codecs) loaded with
   `dlopen(RTLD_LOCAL)` when a Switch 2 game starts, never in a process where MeloNX's Core is
   already loaded (the app asks for a restart otherwise, as for MeloNX's single JIT transaction).
   This avoids two .NET runtimes in one process instead of betting on it.
2. Game code reaches execution through the placement proved on device: pages mapped R|X by the
   process at the module's address in the reserved window, prepared by the JIT helper while
   attached, written through a `vm_remap` alias after detach. Data blocks keep their `MAP_PRIVATE`
   file mapping (no signature needed for RW).
3. S2Arm is changed through a patch series against the pin (as RewindBox does for its other
   engines): no `main`/app delegate, container launch path driven by RewindBox, no process-wide
   `setenv` after start, signal handlers chained, failures returned instead of `exit`/`_exit`.
4. Preparation on the phone produces the same pack the computer pipeline produces (unpack, code
   stage, caps, image pack, companion tables, system data); RomFS read in place.

Milestones, each closed by its own proof:

| --- | --- | --- |
| P0 | ZBIC + export-folder reader ported to C | CI byte comparison with S2Arm |
| E0 | S2Arm's iOS engine builds unmodified in our CI | `make ios` passes; inventory of images and symbols |
| P1 | Pack assembly on the phone (caps, image pack, tables, system data) | CI byte comparison; device run on the maintainer's game (sizes, hashes, time) |
| E1 | Engine as a guest framework (patches) + JIT image loader | CI build; host checks of the loader |
| E2 | Real game boots on device to the services init | journal: modules mapped, `S2A_Init`, first service calls |
| E3 | First frame on device (engine view inside RewindBox, run-time shaders) | journal + maintainer's screenshot |
| E4 | Controller and touch input | maintainer plays |
| E5 | Switch 2 playlist and import flow (with sessions 03 and 02) | final test: import, launch, play |

Coordination: session 01 (JIT helper transaction for the engine, MeloNX exclusivity), main (a new
engine component in the test IPA line), session 03 (playlist files), session 02 (touch skins).

## 7. ZBIC and export folder (unpack route chosen 11 Nov: Switch 2 export folders only)

Ports, local commits on the worktree branch (not yet run in CI at the time of writing):
- `native/s2arm/prepare/s2arm_zbic.c/.h` — `pack/nx_unpack/ZbicDecoder.cs` (zstd with BIC FSE

  segments, same flag rules and bytes, SHA-256 kept and checked). CLI `nso-normalize <in> <out>`

  the device can read the export in place; CI compares the copy mode only.
- `rb_s2arm_prepare_code` normalises ZBIC modules first (work copy `<out>/nsoexe`, removed).

and all their one-byte changes and cuts, `make_synth_zbic.py` frames, header edge cases, NSO
layouts) through both decoders, then the real `nx_unpack --nso-normalize` vs ours.
`run_ns2_dump_test.py`: 30 synthetic export folders, trees compared byte for byte.
`run_code_stage_test.py`: ZBIC cases (reference = `nx_unpack --nso-normalize` then S2Arm's steps).

Verified locally (own code only, ASan/UBSan): S2Arm's frames decode to its `Gen()` text, the

collision check and ASCII-only digits for version/DLC folder names; decompressed segment cap

## 8. Per-game files written on the phone (P1, 11 Nov)

Ports, local commits on the worktree branch (CI not seen at the time of writing):
- `native/s2arm/prepare/s2arm_pack.c/.h`
  - `rb_s2arm_image_pack`: `ios/embed.py` and the parts of `ios/macho_dylib.py` it uses. The
    output is S2Arm's unsigned file byte for byte: the x0/W/x1/x2 blocks (LOAD_BIAS, FAR,
    PATCH2), `S2AEMB01`, LC_UUID, the reserved signature area and the linker-style ad-hoc
    signature. The file is streamed with sparse zero runs and written through `<output>.tmp`.
  - `rb_s2arm_module_dir`: the per-game part of `pack/ship_ext.py container`. It covers
    `place_game` (Horizon load order), the shell's tables (`pkg_srcs.py app_tables()` at the
    pin, compiled in, checked in CI), `icon.jpg`, `banner.jpg`, `save-identity.json` (checked
    as `save_identity.py` does) and the optional `launch.ctx` v1. It is built in `<dir>.tmp`
    and replaces the old directory whole. The image pack is written last.
  - `rb_s2arm_direct_skeleton`: `graphics/tools/direct/runtime_only_lib.sh` as
    `pack/stage_direct.sh` calls it. It writes the empty direct library, with the texts byte
    for byte. The chain version is the shipped engine's (`translator/dmsh_chain.py version()`).
  - `rb_s2arm_resource_pack`: `pack/pkg_srcs.py srcs` and `pack/pack.py`. `index.tsv` and
    `manifest.json` are identical to S2Arm's. `romfs/` and `aoc/` are relative symlinks into the
    product root, so the data is read in place. `systemdata/` is copied or linked. On request
    it adds `.applied` and `index.applied.tsv`, as `runtime/src/pack_apply.c` leaves them.
- `native/s2arm/prepare/s2arm_caps.c/.h`: `pack/gen_caps.sh --both` (target apple) with
  `tools/caps_policy.py decide`, including its engine rule (`profile_guess.py`
  facts_of/guess/engine).
- `s2arm_ns2_dump.c`: `--reference` now builds in-place views instead of the
  `data_sources.tsv` of § 7.
  - `romfs/` is one relative directory link when one export folder holds the whole RomFS and
    nothing is left out.
  - Otherwise it is a tree of file links: a delta update, `.listing`, empty folders and
    `aoc/<n>/` all take this form.
- `s2arm_sha256.c/.h` is an internal SHA-256. The CLI gains `image-pack`, `caps`,
  `module-dir`, `direct-skeleton` and `resource-pack`.

The host runs these steps in order:
1. `ns2-dump --reference`
2. `code`
3. `caps`
4. `direct-skeleton`
5. `module-dir` into `Games/<gid>/` (image pack `S2AImages-<gid>.dylib`)
6. `resource-pack` into `Documents/games/<gid>/资源包`, with the app's system data tree linked and
   `--applied`

The host supplies:
- the save identity: name and version from `control.nacp`, and a content identity that is its
  own hash of the export, because S2Arm hashes NSP/XCI packages that do not exist here;
- the engine's direct chain version;
- the location of the system data tree;
- the `launch.ctx` values, or none.

The game id comes from `main.npdm`.

CI (`s2arm-prepare.yml`):
- `run_pack_test.py`
  - Runs S2Arm's chain: `ns2_dump.py`, the code stage, `gen_caps.sh`, `runtime_only_lib.sh`,
    `ship_ext.place_game` plus the container's per-game steps, `pkg_srcs` and `pack.py`.
  - Next to it, it runs ours on a copied root and on an in-place root. The inputs are eight
    synthetic games: plain, tables + save identity + system data, delta update, RomFS litter,
    Unity, Unreal with and without `.pak`, and an engine exception. The roots are compared
    after every stage, then the module directory and the image pack byte for byte, and the
    resource pack through our links.
  - Six negative cases must fail at the same stage on both sides.
  - It also checks that the table list equals `pkg_srcs app-tables`, and that S2Arm's
    registries do not list the synthetic program id (the premise of the caps port).
- `run_ns2_dump_test.py` gains six view cases. Each checks that the tree seen through the links
  is S2Arm's copy, and that every link is relative and stays inside the export.
- `build_sysdata_bundle.sh` runs S2Arm's generators at the pin.
  - It builds the game-independent `systemdata/`: the 7 open `.bfttf` fonts
    (`make_open_fonts.py`), `010000000000080E` from the pinned IANA release, and every
    `sysdata_need.py` SYNTH id with its `.synth` marker.
  - It adds the licences, `SOURCES.tsv` and `SHA256SUMS`, and is uploaded as
    `s2arm-sysdata-<os>-<sha>`. No font or generated file is in the repository.

Verified locally, own code only, gcc and clang `-Werror`, ASan/UBSan with leak checks:
- The image pack passed a structural checker: header, load commands, index against the input
  blocks for near, bias, FAR and dual layouts, every page hash, CodeDirectory fields. The bytes
  were identical across the three builds.
- The direct skeleton texts are equal to the strings of `runtime_only_lib.sh` read as data.
- `run_pack_test.py --mine-only` passed 14/14: our two chains agree, and the engine rule finds
  the cases above.
- `run_ns2_dump_test.py --mine-only` passed 39/39.

Deliberate differences:
- caps
  - S2Arm's registries (strong signals, 60 fps coverage, A/B and verification ledgers) are not
    on the phone and are taken as absent.
  - The engine rule does not open RomFS files.
- Image pack
  - At most 512 modules, each header value within ±2^40, and the image below 4 GiB (S2Arm
    fails there too).
  - A negative LOAD_BIAS is refused (S2Arm stops in `struct.pack`).
- Module directory
  - Multi-program collections (`programs/<n>/`) are refused.
  - The save identity comes from host values instead of a file.
  - `launch.ctx` is optional.
  - Stale files disappear, because the directory is swapped whole (S2Arm assembles a fresh
    container each time).
- Resource pack
  - It uses symlinks instead of clones, but `index.tsv` is identical. macOS litter
    (`.DS_Store`, `._*`), which the index skips, stays visible through the links.
  - `ui_overlay` and `programs/` are refused.
  - There is no `<pack>.state.tsv`: the pack is always built fresh in `<pack>.tmp` and renamed.
- Direct skeleton: no `game.tsv`. S2Arm copies it only from an NVN profile folder, which the
  phone does not have.

Findings:
- **`romfs.s2aidx`.** It is written at pack time by C# (`pack/stages/romfsidx.sh` →
  `services/romfs_index`, LibHac's RomFS builder layout, `services/S2A.Services/RomFsIndex.cs:15-21`).
  - Without it, the services rebuild the RomFS from the directory at every boot and do not
    cache the result (`Application.cs:120-131`). S2Arm measured about 2.7 s on iPhone for a
    game with over 100k files.
  - Not ported. Option: call the services' own `RomFsIndex.Write` once after preparation when
    the engine framework exists (E1). That avoids re-creating LibHac's layout in C.
- **Time zone.** It can come from the bundle, or be generated by the services when missing
  (§ 6.1).

Open risks:
- Byte identity with `macho_dylib.py`, `pack.py` and the caps texts is proven only by CI.
- `skia-pathops` 0.9.2 needs a wheel for the runner's Python 3.12 (the font step).
- The in-place links break if the export folder is moved or deleted; the host must check
  before launch.
- How the services' .NET directory walk behaves on file links (directory links never occur
  inside `romfs/` or `aoc/`) is to be confirmed on device (E2).
- The module-dir and image-pack calls take no cancel or progress callback yet (a multi-GB pack
  is written in one call).

### 6.3 The engine as a framework (run 43033827604, macos-26, Xcode 26.6)

`build-utils/s2arm/engine/guest.mk` links the objects and libraries of the S2Arm.app executable
as `S2ArmEngine.framework` (patches 0001–0002): 103 MB bundle, binary 107.5 MB (`__TEXT` 41 MB,
`__DATA` 51 MB, `__LINKEDIT` 63 MB), 5 307 exported symbols, 49 Objective-C classes, `_main` and
`S2A_Init` present; NativeAOT library 234 MB before link (399 296 external symbols).

Consequences for the host (decided):
- The engine looks up 85 of its own functions with `dlsym(RTLD_DEFAULT, …)` (`S2A_InitSession`,
  `S2A_ShutdownSession`, `s2a_graphics_shutdown_session`, `nxgal_*`, `nvn_*`…). Opened with
  `RTLD_LOCAL` these lookups would fail silently, so RewindBox opens it with
  `RTLD_NOW | RTLD_GLOBAL`. Third-party exports (libvpx, opus, dav1d, glslang…) can be hidden later;
  the engine does not look them up.
- `rb_s2arm_engine_loaded()` is exported by RewindBox's small host plugin (loaded at app start), not
  by the framework: an atomic flag set before the `dlopen`, so MeloNX's check by
  `dlsym(RTLD_DEFAULT)` sees it even if loading fails. Before opening the engine the host reads
  MeloNX's `rb_melonx_core_loaded()` (session 01, commit `a18490cb`, not in `Claude` yet) and refuses
  with "restart RewindBox" if it returns 1.

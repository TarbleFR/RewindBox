# RPCS3 Core 641 : diagnostics audio dans les journaux de l'appareil (Assassin's Creed), 4 novembre 2026

Core 641 = Core 638 ([fiche](rpcs3-core638-2026-11-03.md)) + [`build-utils/rpcs3/core641-from-638.patch`](../build-utils/rpcs3/core641-from-638.patch),
replié dans le delta canonique (`core641_20261104`, [`core641-delta.json`](../build-utils/rpcs3/core641-delta.json)).

**Texte de journal seulement.** Aucune valeur, aucune cadence, aucun tampon ni aucun réglage audio ne change. Le pont hôte
(`Rpcs3InternalBridgePlugin.mm`) est inchangé : ses octets sont liés par la preuve de dépendance MoltenVK.

## Question bloquante

IPA 640 : le mainteneur entend encore des saccades audio dans Assassin's Creed. Les journaux de l'appareil ne contiennent
aucun compteur audio d'exécution. Le Core écrit pourtant déjà trois lignes cumulées, au niveau notice, au plus toutes les 2 s :

- file cellAudio et producteur cellAudio (`rpcs3/Emu/Cell/Modules/cellAudio.cpp`, `audio_ringbuffer::log_diagnostics`) ;
- rappel de rendu RemoteIO (`rpcs3/Emu/Audio/IOS/IOSAudioBackend.cpp`, `IOSAudioBackend::log_diagnostics`).

Le rappel de journal de l'hôte rejette toute ligne notice qui n'est pas une ligne de profilage (`COREPROF `, …). Aucune de
ces trois lignes n'atteignait donc le fichier. C'est un défaut de journalisation ; la cause des saccades reste inconnue.

## Ce que Core 641 écrit (`REWINDBOX_AUDIO_DIAGNOSTICS_EXPORT_641`)

| Ligne | Champs principaux |
| --- | --- |
| `COREPROF AUDIO641 part=queue cumulative` | `requested_frames`, `delivered_frames`, `starved_frames`, `refill_silence_frames`, `min_fill`/`max_fill`, `recoveries`, `recovery_timeouts`, `not_ready_blocks`, `rejected_blocks`, `untouched_waits`, `in_progress_waits`, `advances_without_mix`, `incomplete_mixes` |
| `COREPROF AUDIO641 part=producer cumulative` | `no_port_silence`, `untouched_silence`, `active_ports`, `target_us`, `period_us`, `tempo_ppm`, `missing_blocks`, `input_rate_ppm` |
| `COREPROF AUDIO641 part=remoteio cumulative` | `callbacks`, `requested_frames`, `delivered_frames`, `filler_frames`, `short_reads`, `zero_reads`, `lock_misses`, `max_gap_us`, `late_callbacks` |

Lecture, sur deux lignes successives d'une même session : une hausse de `starved_frames` ou de `filler_frames` pendant une
saccade entendue signifie une famine du tampon (le producteur émulé est en retard). Une hausse de `late_callbacks` ou de
`max_gap_us` sans famine désigne l'ordonnancement du rappel iOS. Une hausse de `untouched_silence` ou de
`advances_without_mix` signifie que le jeu n'a pas rempli ses ports à temps.

# Build 476 — PS2/PS3 catalogue follow-up

The maintainer reports empty PS2 and PS3 direct cheat lists and a download action without useful feedback in delivered 475. The supplied screenshots show an empty direct list and the PS2 library; they do not establish the exact serial, executable CRC or PS3 executable hash of each running game.

Confirmed PS2 defect: the native snapshot reports a formatted serial such as `SLUS-20655`, while the reviewed PNACH publication stores `SLUS20655`. The catalogue's generic equality check treated them as conflicting even with the same executable CRC. The correction normalizes only valid PS2 disc-serial spellings in both the fast prefilter and the semantic matcher. Different serials, executable CRCs, revisions and PS3 hashes remain conflicting.

Confirmed upgrade defect: a nonempty downloaded index takes precedence indefinitely over a newer bundled publication. A 474 cache can therefore conceal the new 475 PS3 entries. A separately persisted bundle fingerprint now adopts each new bundled publication once; explicit remote updates made afterward remain authoritative for that same bundle generation. Installed chunks, programs and personal patch files are retained.

The in-game download now uses the verified disk/bundled index, prioritizes matching game packs and reuses verified local chunks/packs without an unnecessary remote-index request. The separate catalogue update operation retains remote refresh. Progress and failures appear in the download row itself, including when a host hides the navigation bar. Matching codes refresh during a bulk download and remain usable while unrelated packs finish. Missing extracted chunks can be recovered from a locally cached, subsequently hash-verified pack.

The shared list no longer equates an unavailable native mutation route with no matching catalogue. Matching installed PS3 programs remain visible with disabled switches and the existing translated explanation when a personal patch file is protected or the native route is unavailable. No personal patch is overwritten and no cheat is activated by a download, discovery or import.

Confirmed queue defect: reads of already installed programs were enqueued behind all pending pack downloads. Two separate bounded disk readers now return verified installed chunks while both download workers are occupied; corruption/missing files still go through the bounded pack workers. The Foundation witness deliberately blocks both pack-worker slots and requires an installed PS3 program to be returned before releasing them. The final service-only gate reuses the successful unchanged menu/UIKit source proof instead of executing it again.

Targeted evidence is recorded after execution: exact 475 negative reproduction, real Foundation download/index/offline behaviors for PS2 and PS3, changed iPhone SDK compilation, and seven UIKit cases. The twelve existing translations are reused. All published catalogue data, emulator cores, native helpers, skins, library and NeoSwap inputs remain unchanged. Existing successful checks of those inputs are reused.

Coverage remains edition-specific. The delivered index has no gameplay catalogue titled Budokai 2 or Dynasty Warriors 5, and its GoW/Hobbit PS2 entries do not cover every region. This runtime fix must not invent missing codes or apply another edition's addresses. No physical iPhone gameplay validation or public release is claimed.

The additional source review distinguishes absent coverage from runtime failure. The already reviewed CheatDevicePS2 source is still withheld from publication because its source labels do not establish CRC/serial/region mappings. GameHacking lists Budokai 2 PAL under [SLES-51839](https://gamehacking.org/game/101227), predominantly in encrypted Action Replay formats, and [Dynasty Warriors 5 SLES-53339](https://gamehacking.org/game/101277) with both encrypted and raw programs. Its latter page has a conflicting region field. These are not evidence that the maintainer owns either exact edition, nor a reason to relabel another region's programs as compatible. No incomplete encrypted or guessed conversion is added to this runtime candidate.

The first follow-up revision `125d6774` passed the negative PS2 reproduction, Foundation download/offline checks and iPhone SDK checks. An unnecessary broad workflow triggered by that first commit was cancelled; the later `[direct-followup]` marker selects only the targeted gate. Revision `b60e1a15` adds the old-index upgrade proof; revision `61cceed5bf3deebbdc28dd04160d0207b608eaa5` avoids retaining both parsed index trees during an upgrade. Only the final successful source/run will authorize the IPA. Earlier source results are not counted as final or as additional distinct scenarios.

Final composition: menu/API proof `61cceed5` / `39105809611`, protected-switch UIKit proof `6c41e180` / `39106115226`, and actual catalogue service/blocked-worker/partial-update proof `9af4126d` / `39106305814`. The delivery gate requires every named run to succeed and compares exact source bytes across these boundaries. The final service-only run skips the unchanged menu and fake-service UIKit cases; it executes the actual changed Foundation service and its iPhone SDK compilation. No skipped step is a new pass. The final service witness reproduces both the delivered serial rejection and the old queued-reader failure, then requires both fixes and a changed PS3 edition to be readable before an unrelated download finishes.

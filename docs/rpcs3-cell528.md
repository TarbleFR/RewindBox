## Correctifs implémentés et compromis

- **Transactions NeoSwap :** taille de chunk par défaut 64 → 256 Kio. Une image de 691 200 octets passe de 11 à 3 checkpoints/lectures. Aucun changement de format invité, du contrat ABI ou des contrôles de checksum ; les archives sont propres à la session. Enveloppe managed 8 Mio, staging 4 Mio et RAM Store 1 Mio inchangés. Le workspace backend réservé augmente dans la même enveloppe : avec compression configurée, environ 2,1875 → 2,75 Mio, soit +576 Kio et moins de place disponible pour les autres chunks. Cela peut réduire les transactions sans éliminer une latence du stockage iOS ; il faut surveiller la durée maximale d'un checkpoint et l'attente utility sous pression. La variante 1 Mio exigeait 2 Mio de RAM Store et doublait l'empreinte de l'image arrondie : écartée.
- **Petits textes GLSL :** après création réussie du module Vulkan, les textes de moins de 64 Kio restent dans leur objet shader jusqu'à sa destruction. Les gros textes conservent le chemin NeoSwap. Cela évite les admissions, les vérifications disque et les refus pour tous les textes vus dans le PID 25906. Ce sont les textes de diagnostic CPU, pas les modules GPU ni un nouveau cache de compilation. Dans cette session, environ 2,20 Mio auparavant archivés resteraient en RAM ; ce chiffre n'est pas une limite globale. La durée de vie reste celle des objets existants, sans pool ni copie supplémentaire. Vérifier la hausse de mémoire stabilisée et les pics pendant une session longue.
- **Fichier d'état manquant :** `0x80010006` est `CELL_ENOENT` dans ce cœur. L'id 5 est un fichier régulier en lecture seule, chemin invité de classe `/dev_bdvd/`, sans données embarquées. Les anciens logs ne révèlent pas son nom : aucun nom inventé, aucune réécriture de montage arbitraire. Le chargeur renvoie une cause récupérable avant seek, lecture du tag suivant, callbacks différés et lancement des threads invités. Les objets déjà construits restent destructibles ; les workers reçoivent l'abandon avant libération du verrou global de lancement, puis le nettoyage ordinaire arrête la session. L'état original n'est pas modifié. La trace et le message d'échec de rechargement automatique indiquent le fichier relatif au disque et demandent le même disque/dump et sa mise à jour. Les noms de conteneurs iOS/host_root ne sont pas exportés. La remise en état complète sur appareil reste à vérifier.
- **Historique exploitable :** `RPCS3-performance.log` et `.1.log`, 2 Mio chacun, gardent profils, configuration, freezes complets et cause d'échec de restauration ; les centaines de détails de constructeurs restent dans les logs ordinaires. Travail sur la file de diagnostic asynchrone existante, sans fsync, réserve RAM ou nouveau thread. Les JSON RPCS3 et les exports NeoSwap ajoutent une paire d'horloges monotones encadrant l'heure civile au point de capture. La file d'écriture ne décale plus l'heure mesurée ; les événements NeoSwap doivent toujours être joints à leur capture, pas à l'heure d'export.
- **Coût vidéo attribuable :** `COREPROF VDECIO528` distingue demandes/lectures effectives, prélectures, succès/échecs, temps total et maximum de lecture côté appelant, attente maximum du consommateur et octets chauds actuels/maximum. Compteurs de durée de vie du processus, échantillonnés au rythme du profileur existant. Les lignes `NEOSWAP_VDEC` bornées sont routées vers la même admission que COREPROF. Ces durées recouvrent les lectures parentes NeoSwap.

## Réglages shaders et caches JIT

L'ordre déjà présent est initialisation du Core → publication des profils détectés → prêt au boot. L'avertissement GameDB avant initialisation provient aussi des scans de bibliothèque ; seul, il ne prouve pas un échec de publication lors du boot. Dans les lancements analysés, **legacy_custom=1** désactive la couche GameDB et les overrides clairsemés. Le mode Legacy single-threaded et async_tex=false sont donc les choix persistés effectivement chargés. Aucun choix utilisateur remplacé silencieusement.

Les quatre modes existent dans ce cœur : Legacy (0), Async Recompiler (1), Async avec interpréteur (2), interpréteur seul (3). Les modes 2/3 exigent le support des 64 samplers/images ; Vulkan peut se rabattre sur le mode 0 selon le GPU. `COREPROF SHADERCFG528` donne le mode configuré, appliqué, le support et le repli, sans modifier les réglages. Le test A/B optionnel du mode 1 nécessite une inspection visuelle : aucune promesse d'absence de shaders manquants ou de gain automatique.

Les 136 compilations / 327,309 s du premier boot et les 40 modules en cache / ~0,6–0,7 s des autres boots portent sur des ensembles différents. Les ~534 s cumulées de codegen et ~37 s d'écriture cache incluent du travail parallèle et ne s'ajoutent pas au temps mural. Le premier boot est dominé par de la compilation réellement effectuée, pas un parcours JIT vide de 327 s. Les files incrémentales de publication MCJIT du build 527 sont déjà présentes ; pas de nouveau parcours complet supprimé ni de gain de gameplay revendiqué sur ces logs. `ppu_pipeline=0` signifie pipeline upstream, pas absence d'ARM64/NEON. Les séquences ARM64/NEON validées du build 527 sont conservées. Aucune nouvelle transformation numérique n'est justifiée sans fréquence réelle. Les clés codegen restent **PPU a987639e9f838d1c / SPU e1335a5d6dcd86be**, pour réutiliser les caches 527.

# RPCS3 Core 612 : tests de précision par jeu (torches d'AC, armes de BO2)

Lot du 2 novembre 2026, pour l'IPA privée 612 construite sur la 611 livrée. Aucun réglage par
défaut ne change : le lot donne au joueur les leviers de test et les journaux qui permettent de
trouver, **un réglage à la fois**, la vraie cause des deux défauts graphiques.

## 1. Ce que le lot ajoute

| Élément | Où | Effet |
| --- | --- | --- |
| Page **Graphismes > Tests de précision** du menu en jeu RPCS3 | `Rpcs3SessionMenu.mm`, `Rpcs3InternalBridgePlugin.mm`, `RPCS3InGameLocalization.mm` (12 langues) | 8 réglages par jeu ; chaque choix redémarre le titre ; « Valeur du profil » retire la valeur de test ; « Réinitialiser tous les tests » |
| Valeur réservée `@inherit` de `rpcs3_ios_set_game_setting` | Core, `RPCS3IOS.cpp` / `RPCS3IOSSettings.cpp` | retire une seule valeur utilisateur (`custom_configs/overrides/<JEU>.yml`) ; les autres réglages, sauvegardes et profils restent intacts |
| Réglage expérimental « Position Invariance » (Automatique = BO2 et AC, comme en 610) | Core, `system_config.h`, `RPCS3IOSExperimentalPolicy.cpp` | permet de tester l'invariance de position activée ou désactivée pour un seul jeu |
| Ligne de démarrage `CONFIG_LAYERS part=rsx` | Core, `RPCS3IOSBootDiagnostics.h`, `System.cpp` | valeurs effectives (ZCULL, comparaison de profondeur, précision des shaders, maths rapides Metal, cache de sommets, invariance, soumissions asynchrones, MSAA, VSync…) et clés de test appliquées |
| Census v2 (`FEEDBACK610 … census=2`) | Core, `VKDraw.cpp`, `VKRenderPass.cpp/.h` | compte les passes de rendu réellement ouvertes, et non plus chaque appel |

Inchangés : ABI 30, les 92 exports du Core 611, les identités de génération de code PPU/SPU
(a987639e9f838d1c / 477a3fa442d27917), la dépendance MoltenVK 1.4.2 de la 610, les réglages par
défaut de tous les jeux.

## 2. Les 8 réglages de la page

| Réglage | Clé RPCS3 | Valeurs | Hypothèse visée |
| --- | --- | --- | --- |
| Précision ZCULL | `gpu.zcull_accuracy` | Précise, Approximative, Relâchée (profil AC : Relâchée) | AC A1 : course du ZCULL relâché |
| Désactiver les requêtes d'occlusion ZCULL | `debug.disable_occlusion` | oui / non | AC A1-A3 : requêtes d'occlusion |
| Émuler la comparaison de profondeur spéciale | `debug.emulate_depth_compare` | oui / non | BO2 B1 : comparaison de profondeur sur D32F |
| Désactiver les maths rapides Metal | `advanced.disable_msl_fast_math` | oui / non | BO2 B3 |
| Désactiver le cache de sommets | `debug.disable_vertex_cache` | oui / non | BO2 B4 |
| Précision des shaders | `gpu.shader_precision` | Basse, Haute (défaut), Ultra | BO2 ; « Basse » désactive aussi l'invariance |
| Invariance de position | `experimental.position_invariance` | Activée, Désactivée | correctif 610, à confirmer ou écarter |
| Soumissions MoltenVK asynchrones | `experimental.moltenvk_async_submits` | Activées, Désactivées | AC A5, saccades |

Chaque ligne affiche la valeur du **dernier démarrage**, suivie de « profil » ou « test ».

## 3. Protocole sur l'iPhone (un seul changement à la fois)

1. **Référence** : « Réinitialiser tous les tests », jouer 2 à 3 minutes au même endroit, noter
   l'apparition du défaut et les FPS.
2. Changer **un** réglage, laisser le jeu redémarrer, revenir au même endroit et noter.
3. Revenir à « Valeur du profil » (ou « Réinitialiser tous les tests ») avant le réglage suivant.
4. Après un changement qui modifie les shaders (invariance, précision, maths rapides, comparaison
   de profondeur), Metal recompile les shaders au premier passage : juger au **second** passage.

**Assassin's Creed (BLES00158), torches et lumières murales** :
1. Précision ZCULL → Approximative. Si le scintillement disparaît, la cause A1 est confirmée.
2. Sinon, Précision ZCULL → Précise.
3. Sinon, Désactiver les requêtes d'occlusion ZCULL → oui. Toutes les torches sont alors
   dessinées ; cela coûte des FPS.
4. Soumissions MoltenVK asynchrones → Désactivées (saccades, FPS).
5. Invariance de position → Désactivée, puis Activée.

**Call of Duty: Black Ops II (BLES01717), artefacts sur l'arme et l'avant-bras** :
1. Émuler la comparaison de profondeur spéciale → oui.
2. Précision des shaders → Ultra.
3. Désactiver les maths rapides Metal → oui.
4. Invariance de position → Désactivée, pour vérifier si le correctif 610 aide ou gêne.
5. Désactiver le cache de sommets → oui.
6. Précision ZCULL → Précise.

À envoyer après chaque série : les journaux RPCS3 de l'app. Ils contiennent `CONFIG_LAYERS
part=rsx`, les lignes `game_setting … test=1` et les compteurs `FEEDBACK610 census=2`. Le gel de
BO2 au passage en multijoueur avec bots reste une investigation distincte.

## 4. Vérifié sur l'hôte (Linux, pas d'iPhone)

- `test/rpcs3_graphics_tests612_test.py` vérifie :
  - le contrat de l'app (liste blanche = page, `@inherit`, routage, redémarrage même après un refus,
    zone de capture, 12 langues) ;
  - le contrat du Core ;
  - le formateur réel et les corps extraits de retrait d'une clé, exécutés sous g++ ASan/UBSan.
- Tests adaptés au Core 612 :
  - census v2 (forme revue, 3 mutations rejetées) ;
  - invariance de position (chaîne glslang → SPIR-V → convertisseur MoltenVK : PASS) ;
  - RetroAchievements (hooks toujours présents, ASan/UBSan).
- Route du Core :
  - `rpcs3_core610_route_test.py` ;
  - fermeture de sources de la porte sur un arbre 612 matérialisé ;
  - les 10 harnais Apple répétés localement avec g++ ;
  - les preuves Apple du Core 610 réutilisées et authentifiées (audit codegen re-dérivé à
    l'identique).
- Syntaxe Objective-C++ du nouveau code (clang contre une Foundation minimale ; pas de SDK iOS
  ici).

## 5. Limites

- Aucun résultat iPhone : ce lot ne prouve pas la disparition d'un défaut.
- Le Core 612 doit encore être compilé par la route Core (macOS), puis livré par la recette
  standard.
- Le pont, le menu et les traductions ne sont compilés avec le SDK iOS que par la livraison.

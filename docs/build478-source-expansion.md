# Private Build 478 — gameplay sources and 60 FPS patches

The maintainer requests broader PS2/PS3 gameplay coverage, specifically Bladestorm BLES00113, and available 60 FPS patches in Cheats for embedded emulators. Work remains on `Claude`; no public release. Delivered 477 is retained as a separate binary.

The four public BLES00113 gameplay programs are already in 477, explicitly labeled **01.00** in NetCheat and Artemis. No source reviewed so far establishes those offsets for another version. The installed APP_VER on the maintainer's device is unknown; an IRD disc VERSION is not proof of APP_VER. The menu now shows its observed serial/revision and, when no compatible edition exists, reports other source revisions without offering them for import. Known serial, CRC, PPU, revision, region and language conflicts remain enforced. This does not claim the device-specific Bladestorm issue is resolved.

## Source additions

- PSX Data Center PNACH v2.0, the European collection by complicatiion, ShadowNinja, YukiXXL retail PNACH selections and xGamingDragon93x's data-only RAR. CRCs and any serials come from the source files, never from inferred regional titles. Prototype/demo/experimental paths, ambiguous or malformed bodies and unproven group boundaries remain excluded. No code is shortened to its supported lines.
- Artemis mode-0 programs containing only complete aligned static 32-bit writes within the retained adapter's low-address range. Explicit source serial and version, observed runtime PPU binding and edition confirmation remain mandatory. Freeze, RAM, pointer, scan, arithmetic, variable and other width programs remain unavailable. Authored native PPU documents from the PaauloSilva collection supplement the retained ChiDreams input; its MIT notice is bundled.
- Explicitly labeled 60 FPS selections from PCSX2's distributed patches, Gabominated, NetherSX2 and the pinned illusion mirror of RPCS3's server publication. Whole native documents, authors, exclusive groups and source requirements remain intact. No emulator setting changes automatically. PSP, PS1, N64/NDS and Dolphin sources already in the catalogue are inventoried from the real packs; no broad compatibility is inferred from a source website.

The retained Azahar core's cheat callback is a no-op with no usable CheatEngine export. The Switch and Wii U hosts have no validated native cheat import route, and Flycast is absent from the 34 delivered libretro cores. Their 60 FPS databases are not represented as executable codes. No engine is rebuilt or mislabeled to inflate coverage.

Exact pins, SHA-256 digests, per-source contributions, rejected members and publication counts are generated in `tools/cheats/sources478.json`, `native/cheats/catalogue/audit.json.gz`, `docs/evidence/cheats478-sources.json` and `docs/evidence/cheats478-fps.json`. All 44,794 old chunk hashes and 859 old packs remain unchanged. For overlapping exact identity groups, only the current manifest's presentation part count can increase; old chunk bytes keep their original snapshot count. New parts are appended under deterministic distinct IDs. Duplicate-source attribution and whole programs rejected by the native PNACH parser are stored separately without rewriting installed chunks.

## Validation and retained preparation failures

The generator validates the pinned source inputs, complete-program scope, ordered-program deduplication, compressed limits and actual portable PNACH parser acceptance. A full active-pack integrity check, exact published Foundation/native staging, full-index memory probe, changed iPhone SDK compilation and fourteen targeted UIKit cases are required before a candidate. All unchanged successful 477 core/helper/library/NeoSwap/skin proofs and precompiled images are reused, not claimed rerun.

Retained local preparation findings: the first delta reader mistook a retired old pack member for its active replacement; the reader now selects by both ID and active pack ID. One negative fixture exposed a leading `Demo/` path not covered by a slash-prefixed filter; the filter now handles leading paths. Neither failure was published. The actual PNACH parser also rejected long/invalid names, malformed instructions and empty blocks accepted by Python syntax alone; those entire programs are excluded and preserved in the audit.

# Sélection des buffers de constantes

Les versions 0426, 0436 et 0447 ont le même WidenSession.cs. Quatre variantes combinent les masques de slots utilisés par le shader et de slots liés pour réduire le travail de CamReads et BuildReads. Treize triplets alternent dans un ordre pseudo-aléatoire fixe la référence, le premier masque et une autre variante. Chaque processus .NET 10 exécute un échauffement puis 100 000 sélections, sur le CPU Linux x86-64 numéro 1. Pour reproduire l'une des trois séries dans un nouveau fichier, utiliser `python3 replay.py ARBRE_PRÉPARÉ tuple mesures.csv --cpu 1`, en remplaçant `tuple` par `hybrid` ou `split` pour les autres séries.

Pour un seul slot utilisé et tous liés, les médianes du troisième essai sont de 26,868 ms pour la référence et 6,751 ms pour la variante tuple. Quand un seul slot par étage est lié, elles sont de 4,317 et 4,384 ms. Les trois autres variantes ont aussi une médiane plus élevée que leur référence dans ce cas. Les chemins chronométrés allouent zéro octet par thread dans les deux versions. Le contrôle complémentaire couvre 4 096 sélections et vérifie les descripteurs de caméra. La réécriture est désactivée dans ce scénario, le coût mémoire permanent par shader et les lectures de constantes réécrites restent à établir. Aucun de ces changements n'est activé dans le moteur.

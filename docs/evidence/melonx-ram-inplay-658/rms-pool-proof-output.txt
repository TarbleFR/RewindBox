Conclusion: the default pools are unbounded (a disposed stream's 128 KiB blocks stay live in the pool for the life of
the process). Not adopted for Core 658 on iOS: with memoryManager=HostMappedUnsafe on ARM64 the CPU engine is
LightningJit (ArmProcessContextFactory.cs), whose LoadDiskCache returns DummyDiskCacheLoadState, so the PTC carriers
(Ptc.cs) and ARMeilleure's CodeGenContext streams (never disposed, Arm64/CodeGenContext.cs) do not run. The remaining
MemoryStreamManager.Shared users (IPC ServerBase streams, shared-font decryption, ShaderBinarySerializer.Pack,
string/applet helpers) peak at a few MiB of pooled blocks. MeloNX's ObjectPool<RecyclableMemoryStream> wrapper is inert:
ReleaseStream has no caller, so every GetStream creates a new stream and nothing keeps disposed streams.

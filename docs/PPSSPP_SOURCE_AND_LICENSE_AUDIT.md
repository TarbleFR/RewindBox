## FFmpeg: provenance and the license-string inconsistency

The upstream [VENDORED.md](https://github.com/hrydgard/ppsspp/blob/1bd28b0d634d4ec31acb7092563f3e1e247d1e9c/ffmpeg/VENDORED.md)
identifies **libretro-fork/ppsspp-ffmpeg**, revision
[`6c64b8f98ad0ca38f5360484618e2af6e44fcb3d`](https://github.com/libretro-fork/ppsspp-ffmpeg/tree/6c64b8f98ad0ca38f5360484618e2af6e44fcb3d).
That identifier must not be mislabeled as a commit in the main FFmpeg repository.
All **2,624** vendored files in the five library trees and `compat` match that
fork by Git blob identity. NeoStation's functional patch changes none of them.

The historical recipe calls the pinned CMake build, not FFmpeg's configure
script. Its [config.h.in](https://github.com/hrydgard/ppsspp/blob/1bd28b0d634d4ec31acb7092563f3e1e247d1e9c/ext/ffmpeg-build/config.h.in)
contains a fixed `FFMPEG_LICENSE` value of `GPL version 2 or later`, while
`CONFIG_GPL`, `CONFIG_NONFREE`, `CONFIG_VERSION3`, `CONFIG_GPLV3` and
`CONFIG_LGPLV3` are all literal zeroes. These definitions have no substitution
placeholders. `configure_checks.cmake` writes the template through
`configure_file(... @ONLY)`.

Five functions in the vendored library sources return the generated license
string. Static inspection of the hash-verified existing PSP binary confirms
the five `libav*` / `libsw*` GPL-version-2-or-later strings. It also confirms a
placeholder configuration string, not a record of actual configure options.
The binary was neither executed nor modified.

A leading-notice scan of the 273 selected units identifies 269 LGPL
declarations and four other/inherited notices: Adler-32, faandct, jfdctfst
and jrevdct. The GPL-guarded blocks in selected `me_cmp.c` are behind the
zero-valued `CONFIG_GPL` switch. These are concrete source-selection facts,
not a legal classification of the whole linked core. The metadata conflict
remains explicit. Both GPL2 and LGPL2.1 texts are retained, and no LGPL-only
binary claim is made. The historical identity's inherited `license: GPLv2`
field is also not treated as a complete dependency classification.

No NeoStation change was made to those FFmpeg sources.

It supplies the actual named copyrights and terms for selected Snappy,
glslang, SPIRV-Cross, cpu_features, udis86, the Android GL stub and the
Dolphin/crypto inputs. The Bison exception and differing original GPL
version labels are preserved. Copyrights and permissions were not rewritten;
only source headings and scope explanations were added. The manifest records
the original source blob and extracted-region SHA-256 for each input.

[SOURCE-MODIFICATION-NOTICES.patch](../assets/legal/ppsspp/SOURCE-MODIFICATION-NOTICES.patch)

Its application check passed after the functional patch and ABI copy. It is
not applied by the product recipe and was not part of the historical compiler
input. Before/after hashes make this distinction reviewable.

The GPL v2's [sections 1, 2(a) and 3](https://www.gnu.org/licenses/old-licenses/gpl-2.0.en.html)
require the applicable preservation, modification-notice and source-distribution
steps. The LGPL v2.1's [sections 4 and 6](https://www.gnu.org/licenses/old-licenses/lgpl-2.1.en.html)
address library source and the applicable relinking/source route for combined
works. The complete original texts accompany this record. Retaining only a
license text or a third-party URL does not complete the corresponding-source
step for a future binary distribution.

## Capsule contents, exclusions and recreation

The capsule exports pristine source Git blobs and keeps the exact functional
patch, ABI and recipe separately. It includes the compiler log, existing
identity metadata, static-license-string evidence, all collected notices and
a per-member SHA-256 manifest. It includes no Git database, credentials,
core binary, IPA or binary artifact ZIP.

Five upstream compiled files are omitted and identified by hash in the receipt:
`Tools/SaveTool/kernelcall.prx`, the armips MIPS relocation test object,
`ext/vulkan/iOS/Frameworks/libMoltenVK.dylib`,
`ext/vulkan/libvulkan.so.1.3.236` and
`ext/vulkan/macOS/Frameworks/libMoltenVK.dylib`.
None is a logged Build 497 source translation unit. Original source assets
and test data otherwise remain present.

The self-contained recipe is `tools/recreate_capsule.py` inside the archive;
`metadata/README.md` gives exact retrieval and source-materialization commands.
It reads pinned Git objects, checks host-input hashes, preserves original
source licenses, excludes compiled objects and normalizes tar ownership,
timestamps, ordering and gzip metadata. All 13,500 manifest-listed entries
were checked, including 13,446 Git blob identities. Recreating the archive
from its extracted recipe and metadata produced exactly the same bytes and
SHA-256 in this environment. This is a source-capsule reproducibility check,
not an emulator rebuild.

## Limits before a future release

The historical artifact did not retain generated FFmpeg `config.h`,
`CMakeCache.txt`, per-object dependency files or an exact CMake version.
The log records Xcode 26.3 (17C529), iPhoneOS SDK 26.2, AppleClang
17.0.0.17000604, arm64 and iOS deployment target 18.0. The fixed license
switches are traceable, while the full historical generated configuration
cannot be claimed byte-identical. No bit-for-bit binary reproduction was
attempted.

The original packaging recipe also requires the existing 35-core base
package. That binary package is outside this PPSSPP source capsule. Other
buildbot cores and native dependencies retain their separate provenance gaps.
The future source-distribution location, applicable aggregate licensing terms
and the FFmpeg metadata discrepancy must still be handled before publishing
a release. This audit keeps `whole_application_source_complete` false.

## 3. Étapes pour une session qui a ces accès

Dans cet ordre, sur `Claude` à jour, avec **tout l'historique** (`git fetch --unshallow`) : sur un clone superficiel, le gel
reste bloqué sans rien dire. Aucun nouveau commit MeloNX après le gel de l'étape 1.

1. **MeloNX Core 631.** Installer le SDK .NET 10.0.100, matérialiser les quatre contrôles depuis l'archive 614, passer
   les dix portes avec `--candidate-source` sur une préparation fraîche, lancer `freeze_dma_core.py` avec `--receipts` et
   `--control`, puis les deux tests de contrat. Détail :
   [`melonx-629-encoding-2026-11-03.md`](melonx-629-encoding-2026-11-03.md).
2. **Compilation MeloNX.** Commit `[melonx-dma-core]` sans `[skip ci]`. Une fois le run réussi, écrire
   `build-utils/melonx/dma-core-pin.json` et mettre `FRESH_GATES = 10` dans
   `.github/diagnostics/melonx_dma_core_component.py`.
3. **Épingle RPCS3 Core 634.** Télécharger les artefacts `13261039942` et `13261452573` (références complètes au tableau
   des tâches, `TASK-634-RPCS3`), les vérifier avec `rpcs3_core_component.pin_errors` et `bundle`, puis écrire
   `build-utils/rpcs3/core-pin.json`.
4. **Manifeste.** Générer `build-utils/delivery-635-recipient.pem` et garder la clé privée hors de Git. Compléter le
   brouillon `build-utils/delivery/635.json` : destinataire, empreintes des deux pins, commits revus ajoutés depuis.
5. **Contrôle et gel.** `python3 -B test/standard_delivery_contract_test.py`, puis
   `python3 -B .github/diagnostics/standard_delivery.py contract 635`, puis `freeze 635 --dry-run`, puis `freeze 635`.
6. **Déclenchement.** `standard_delivery.py trigger-paths 635 build-utils/delivery/635.json`, puis commit du manifeste gelé
   avec le sujet `[ipa-delivery:635] …`.
7. **Après le run.** Télécharger les 4 pièces et les métadonnées, lancer `build-utils/verify_downloaded_delivery.py`, puis
   `standard_delivery.py record 635 …`. Supprimer la clé privée. Remettre l'IPA au maintainer.

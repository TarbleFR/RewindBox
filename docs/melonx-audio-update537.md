# Private Build 537 — MeloNX audio and automatic update targeting

The supplied `app(9).log` contains several historical runs. The current PID 82724 sessions reach the first Metal frame and close normally. Their `PcmInt16` to `PcmFloat` conversion warning is expected for the Apple backend; it is not evidence that conversion corrupts sound. The user clarified that the symptom is choppy/crackling sound. No physical-device cure is claimed from this log or the short recording.

Upstream `Library.cs` actually selects `AppleHardwareDeviceDriver`. Build 533's SDL3 correction therefore did not address this playback path. The Apple player previously started before any PCM was available, leaving no scheduling lead for the 5 ms DSP blocks. It now starts from the first real buffer with a 20 ms host-time lead, serializes scheduling with disposal, and restarts an engine stopped by a route/session change. The frontend's ambient audio observer also used to overwrite MeloNX's playback category, including in response to that category change itself. Ownership is now explicit until game closure, and activation is repeated after the frontend device closes during presentation. Actual output rate, I/O duration and route type are recorded in the internal application journal.

The playlist-wide update action ignores the merely highlighted game and reads the NSP's native CNMT/NCA identity, finds the installed base game by title ID, and names that game in the result. Legacy rows without IDs use native metadata without hashing the game files. Missing games, incompatible content and ambiguous multi-game packages are refused before copying. Per-game imports and batch DLC imports remain supported. New messages cover all twelve supported locales.

Validation: twelve targeted Flutter service/widget tests passed locally against the exact committed inputs. The production Apple session compiled against a timed AVFoundation double reproduced 720 missing frames before the fix and zero afterwards, preserving every PCM frame; twenty-one fixed-path assertions also cover short buffers, pause/resume, deferred interruption recovery, engine restart, volume and update selection. This is deterministic backend coverage, not measured iPhone sound quality. The macOS host job additionally compiles the actual iPhone Swift modules, executes production audio ownership methods with a session double, and exercises registered UIKit presentation. The rebuilt NativeAOT engine must pass its actual ARM64 iOS app smoke test before delivery.

The IPA recipe retains the source-built RPCS3 536 core and its successful Foundation logger evidence, along with the other unchanged engines. Existing successful checks are reused only with matching source inputs. The final signed package is checked for the new native and Flutter code, source receipts, versions, exports and extension structure. Distribution remains a private test IPA for SideStore re-signing; no release, main-branch change, physical installation or commercial-game audio validation is implied.

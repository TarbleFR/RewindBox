# S2Arm engine for the Switch 2 test line

Patches applied in order to S2Arm at the commit of `tools/s2arm_prototype/pin.json` by
`.github/workflows/s2arm-engine.yml`. Each patch says why it exists; the S2Arm source itself is
fetched at build time and never committed here (Apache-2.0, see `docs/s2arm-legal-notices.md`).

| Patch | Why |
| --- | --- |
| `0001-ios-sdk-older-than-27-without-scene-accessory.patch` | GitHub's macOS images carry Xcode 26.x (iOS SDK 26.2 / 26.5); S2Arm is built with the iOS 27 SDK and `ios/extdisplay.m` uses its scene-accessory API. Built with an older SDK the engine does not take over external displays, as on a device below iOS 27. |
| `0002-engine-image-header-without-mh-execute-header.patch` | Linked as `S2ArmEngine.framework` (a dylib) the engine cannot reference `_mh_execute_header` (run 43030882887: the only undefined symbol). Seven uses read the engine's own registration sections (`__DATA,swnvn/swhle/swgl/swglb/swvkb`) or `__TEXT` range, which live in the framework: they now take the header of the image that holds the code (`runtime/src/rb_selfimg.c`, `dladdr`). The entitlement fallback of `ios/iml_probe.m` reads the process's main executable (`_dyld_get_image_header(0)`). In the S2Arm.app executable both give the executable's header, so its behaviour is unchanged. Apple platforms only. |
| `0003-guest-configure-launch-context-and-window.patch` | Loaded by RewindBox (`dlopen` of `S2ArmEngine.framework`), the engine does not know the game when its constructors run: `vawin_boot` (`runtime/src/vawin.c`, constructor 101) would freeze the launch context from RewindBox's executable directory and `HOME` and size the address window from a `main.npdm` that is not there. When RewindBox loaded it (the engine is not in the main executable and the process exports `rb_s2arm_engine_loaded`, the host plugin's symbol, which the engine only looks up) the constructor leaves both alone; S2Arm.app, also inside LiveContainer, has no such export. `s2a_rb_guest_configure` (new `runtime/src/rb_guest.c`, public header `runtime/src/rb_guest.h`, copied into `Headers/` by `guest.mk`) takes the game's paths from the host, freezes them as a file-type launch context (`s2a_launch_ctx_set_guest` in `launchctx.c`: same checks and defaults, environment written as S2Arm does, never a container), then runs the constructor's own window reservation and the .NET GC limit S2Arm's `main` sets after it. S2Arm.app: unchanged. |
| `0004-guest-code-pages-through-host-hook.patch` | RewindBox cannot code-sign the image pack it writes on the phone. In a guest the pack is opened without `F_ADDFILESIGS_RETURN` / `F_CHECK_LV`, and every code block (`s2a_imgpack_map` code branch, which serves the boot modules, nn::ro NROs at run time and the in-process restart) goes to the host's `prepare_code(address, length)`: the host makes the pages executable and returns a writable alias, the engine `pread`s the block into it and invalidates the instruction cache. Data blocks keep their file mapping. The in-process restart keeps those pages for reuse (`vawin.c` `s2a_window_session_reset` takes its per-segment path, which never replaces code pages), as it keeps signed ones. Off unless configured. |
| `0005-guest-signal-handlers-chained.patch` | S2Arm installs its SIGSEGV/BUS/ILL/TRAP/FPE/ABRT handler without keeping the previous one. In a guest the previous action is kept; a fault the engine does not claim (not tracked or emulated, pc outside the game's modules and the engine's own code) goes to it, and the crash report re-raises through it instead of `SIG_DFL` (model: the Android variant, `crash_android_fatal.inc`). Nothing is kept in S2Arm.app, so both paths behave as before there. |
| `0006-guest-session-end-instead-of-exit.patch` | An orderly end (`lifecycle.c`: the game exits, "quit game", the 1.5 s fallback) finishes with `_exit(0)`, which would close RewindBox. In a guest the host's `session_ended(0, reason)` is called and the shutdown thread parks (SIGTERM still exits; the app's own termination returns to UIKit). Start failures, the self-check page, the renderer and GPU-stop pages, the stall watchdog and `die()` (outside signal handlers) call `session_ended` with S2Arm's exit status first and otherwise keep their behaviour; a game Break no longer shows S2Arm's resource-pack help in a guest. Weak defaults keep S2Arm's per-file unit tests linking and are S2Arm.app's behaviour. |
| `0007-guest-view-controller-and-start.patch` | No `UIApplicationMain`, app delegate or scene delegate in a guest: `s2a_rb_guest_make_view_controller` builds the game view controller as `enterGame` does once a game is chosen, `s2a_rb_guest_start` runs `sceneDidBecomeActive` → `startHost` on it (save manager first when requested, monitoring, touch pad, host thread) and keeps `s2a_front_run` from ever entering `UIApplicationMain`. The touch pad's menus present from that controller instead of the window's root view controller (the host presents it, so it is not the root). |
| `0008-guest-strings-and-game-files-from-engine-bundle.patch` | The host app's main bundle has none of the engine's string tables: `S2AL` / `S2APICK` (`ios/s2a_l10n.h`) read the bundle of the image running the code (the main bundle in S2Arm.app, the framework directory once a guest is configured, where `guest.mk` copies `<lang>.lproj`). Save management takes `save-identity.json` and its per-game key from the launch context's module directory, as for a container game. |

The diagnostics package, MetricKit payloads and the session marker follow the log into `docs`. The load page, HUD, diagnostics, community patch list and NS2Pro loader read the engine's bundle (S2ArmEngine.framework; NS2Pro.framework next to it) instead of the host app's; `guest.mk` writes `S2ACommit` into the framework's `Info.plist` as `make ios` does for S2Arm.app. |

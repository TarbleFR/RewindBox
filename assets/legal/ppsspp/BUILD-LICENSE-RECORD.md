## What the existing build actually selected

The retained compile log from run `39455712245`, artifact `12281188239`, was
retrieved and its previously recorded archive hash was verified. It records
631 core translation units and 273 FFmpeg C translation units. Every logged
core object appears in the final link command. Five FFmpeg static libraries
are linked: avcodec (145 units), avformat (43), avutil (63), swresample (8)
and swscale (14). One core unit, `git-version.cpp`, is generated by the
makefile; its contents are reconstructed from the recorded recipe, not claimed
to have been captured from the build worker.

The iOS recipe builds FFmpeg through `ext/ffmpeg-build/CMakeLists.txt`.
It does not invoke FFmpeg's usual configure script. The config template
contains these literal, non-substituted settings:

```c
#define FFMPEG_LICENSE "GPL version 2 or later"
#define CONFIG_GPL 0
#define CONFIG_NONFREE 0
#define CONFIG_VERSION3 0
#define CONFIG_GPLV3 0
#define CONFIG_LGPLV3 0
```

`configure_checks.cmake` copies that template with `configure_file(... @ONLY)`.
Five FFmpeg license functions return the resulting license string. Independent
static inspection of the historical core, after verifying its SHA-256
`a7d058581b657714e055dc9713e9a1252ad4acf6315b30610fcb2b1c81130b6f`,
confirms the five corresponding GPL-version-2-or-later strings. The binary
also contains a placeholder configuration string, not a record of configure
options. It was not executed, modified or rebuilt for this inspection.

## Interpretation and file-specific notices

The disabled GPL/nonfree/version3 flags coexist with the GPL license string.
The vendored `ffmpeg/LICENSE.md` describes LGPL-2.1-or-later as the default,
with optional GPL parts. A leading-notice scan of the 273 selected units
finds 269 LGPL declarations and four other/inherited declarations: Adler-32,
faandct, jfdctfst and jrevdct. The GPL-guarded blocks in selected `me_cmp.c`
use the zero-valued CONFIG_GPL switch. These observations explain why the
license string alone cannot identify the applicable source terms; they do
not resolve the inconsistent metadata or certify an LGPL-only binary.

Both LGPL2.1 and GPL2 texts remain included. The IJG acknowledgment is kept,
along with the unmodified IJG notices, the additional faandct and Adler-32
notices, and file-specific dependency copyrights. The original source trees
retain their own terms. The historical package's inherited `license: GPLv2`
field is not a complete dependency classification.

FreeType, dlg, rapidjson and its gtest submodule are initialized by the
recipe but have no compiled source units in this log. OpenXR contributes
headers; no OpenXR-SDK loader library appears in the link command. The armips
filesystem submodule is initialized, while ARMIPS_USE_STD_FILESYSTEM selects
the standard-library implementation. These distinctions do not remove the
original licenses from the preserved source capsule.

## Source distribution preparation and remaining limits

`NEOSTATION-MODIFICATIONS.txt` records the exact functional changes and dates.
`SOURCE-MODIFICATION-NOTICES.patch` provides prominent dated comments for the
four modified/added files as a separate source-distribution overlay. That
comment-only overlay is not part of the historical compiler input and is not
applied by the product build recipe. Before/after hashes distinguish it from
the exact historical sources.

No generated FFmpeg config.h, CMakeCache.txt, per-object dependency files or
exact CMake version was retained in the historical artifact. The audit has
not performed a rebuild, reproduced identical binary bytes, or established
every preprocessor branch and static-library member retained in the final
image. It preserves the corresponding source revisions, all initialized
submodule trees, patch, ABI, recipe and available evidence for review.

Distributing a modified core requires the applicable source/build inputs and
notices to be made available under their terms. A license snapshot, an upstream
URL, or a local source capsule alone is not a completed distribution step.
